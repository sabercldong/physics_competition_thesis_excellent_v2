# P0第一批真实回填等待室更新

任务编号：`G1-07-FOLLOWUP-MANUAL-P0-BATCH1-RETURN-WAITING-ROOM-UPDATE`

## 性质声明

本文件只更新P0第一批真实回填链条的等待室状态。它基于P0第一批回填模板、交接包索引、接收准备检查和接收准备QA，说明哪些事项必须等待真实回填，哪些准备工作可以继续推进，哪些正式产出必须冻结。本任务不创建真实回填目录，不填写校对人、日期、OCR决定、公式决定或放行判断，不关闭任何人工校对项，不修改题文，不生成正式编码、正式统计、论文正文或 `final_coding.csv`。

## 当前判断

P0第一批38个题目级小批次已经具备以下准备材料：

- 空白真实回填模板；
- 字段级填写说明；
- 交接包索引与交接包QA；
- 接收准备检查与接收准备QA；
- 可挂接的通用接收协议、登记模板和目录规则。

但是，当前仍未收到P0第一批真实回填副本，也未创建 `03_corpus/manual_review_returns/`。因此，P0第一批仍处于“等待真实回填”状态，不能进入人工销项、正式评分者模板、正式编码、正式统计或论文结果写作。

## 三类任务边界

### 一、必须等待真实回填

以下动作必须等真实回填副本出现后才能执行：

- 填写38行校对人、校对日期、OCR决定和公式决定；
- 记录真实核对页、证据摘记、修订位置和剩余疑点；
- 判断是否允许进入正式评分者模板；
- 登记真实文件名、副本路径、SHA-256、文件大小、接收日期和经手人；
- 对真实回填副本做结构检查、不可变字段检查和字段完整性检查；
- 判断38个小批次是否形成关闭候选；
- 更新人工校对总清单或正式评分者模板。

### 二、可继续准备

没有真实回填时，仍可推进以下低风险准备：

- 维护回填接收协议、命名规则、隔离规则和冲突分级；
- 准备真实副本接收后的结构检查脚本或检查清单；
- 整理P0第一批对正式评分者模板的字段影响说明；
- 整理其他智能体可执行的逐题核对任务卡；
- 维护正文禁写边界、状态说明和项目台账；
- 继续文献、理论、学校格式、数据管理和复现脚本接口等不依赖真实回填的准备工作。

这些准备只提高接收和整合效率，不能提高证据等级，也不能释放正式结果。

### 三、禁止推进

在真实回填副本收到并通过整合QA前，禁止推进：

- 把P0第一批38个小批次写成已校对完成；
- 关闭第一批76条OCR、公式与特殊符号问题；
- 将P0第一批全部放入正式评分者模板；
- 复制内部编码生成 `final_coding.csv`；
- 运行或发布正式统计表、图、趋势、共现或显著性结果；
- 修改第四章正式结果；
- 升级依赖人工终核或正式结果的主张证据等级；
- 把Codex、模板、QA或内部预演写成真实专家、导师、竞赛教师或评分者意见。

1. 若收到真实回填副本，优先执行接收登记和接收QA，不继续等待室循环；
2. 若仍未收到真实回填，只能推进“可继续准备”类任务；
3. 任何接收、整合、销项、正式编码、正文更新都必须分任务提交；

5. 正式结果链只在真实回填、正式A/B评分者编码、一致性检验、分歧裁决、`final_coding.csv` 和复现QA完成后解锁。
