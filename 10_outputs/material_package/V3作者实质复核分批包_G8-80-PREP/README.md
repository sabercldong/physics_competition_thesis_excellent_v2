# V3作者实质复核分批包

任务编号：`G8-80-PREP`

生成日期：2026-07-30

## 一、用途与边界

本目录把G8-79的884行空白回填表按题目级最高优先级拆成三个可分别回填的文件，降低单次打开、保存和校验的负担。

分批只改变工作文件的组织方式，不改变候选字段、作者复核要求或G8-80接收门槛。目录内文件均为空白模板，不代表作者已完成复核，也不能据此生成V3唯一编码表或论文统计。

## 二、文件清单

| 批次 | 文件 | 题目数 | 复核行数 | 建议顺序 |
|---|---|---:|---:|---|
| P0 | `P0_高优先级_89题356行_空白.csv` | 89 | 356 | 第一批 |
| P1 | `P1_L3边界_89题356行_空白.csv` | 89 | 356 | 第二批 |
| P2 | `P2_常规边界_43题172行_空白.csv` | 43 | 172 | 第三批 |
| 清单 | `V3作者实质复核批次清单.csv` | 221 | 884 | 路径与命令索引 |

每个分析单元的四个维度都位于同一批次。批次依据题目索引中的 `item_priority` 分配，因此P0文件中可能包含个别行级 `review_priority=P1` 或 `P2` 的记录；它们属于同一个P0题目，必须一并复核，不得删除。

## 三、回填方法

1. 先阅读 `09_quality/第35至42届科学思维V3作者实质复核填写说明_G8-79.md` 和 `04_framework/科学思维编码手册_V3.md`。
2. 复制待处理批次，不覆盖文件名带“空白”的模板。
3. 按题目逐组阅读题干、参考解答和四维候选证据，填写全部13个作者回填字段。
4. 同一题目的四行填完后再进入下一题。P0、P1、P2均须全量完成。
5. 每批完成后运行对应的成品校验命令；只有 `errors=0` 才能进入合并。

建议完成副本命名：

- `P0_作者实质复核_<复核代号>_完成_<YYYYMMDD>.csv`
- `P1_作者实质复核_<复核代号>_完成_<YYYYMMDD>.csv`
- `P2_作者实质复核_<复核代号>_完成_<YYYYMMDD>.csv`

## 四、逐批校验

在项目根目录运行：

```bash
python3 07_analysis/scripts/validate_v3_author_review.py \
  "<P0完成副本路径>" --mode filled --item-priority P0

python3 07_analysis/scripts/validate_v3_author_review.py \
  "<P1完成副本路径>" --mode filled --item-priority P1

python3 07_analysis/scripts/validate_v3_author_review.py \
  "<P2完成副本路径>" --mode filled --item-priority P2
```

## 五、合并与全量校验

三批都通过后运行：

```bash
python3 07_analysis/scripts/merge_v3_author_review_batches.py \
  "<P0完成副本路径>" \
  "<P1完成副本路径>" \
  "<P2完成副本路径>" \
  --output "07_analysis/data/第35至42届科学思维V3作者实质复核回填表_合并待验.csv" \
  --mode filled
```

合并程序会检查表头、逐行不可变字段、批次行数、重复项和完整并集，再按原始884行顺序输出，并自动执行全量成品校验。校验失败时，程序会删除失败的合并输出。

## 六、接收要求

提交G8-80接收QA时，应同时保留：

- 三个完成副本原件；
- 合并后的884行文件；
- 四个文件的SHA-256；
- 实际复核人或匿名代号、实际复核日期和与事实一致的复核声明；
- 逐批与全量校验输出。

结构校验通过只证明字段、顺序和逻辑符合规则，不证明身份真实性或学术判断正确。
