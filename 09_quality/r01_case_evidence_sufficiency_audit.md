# R01 正式案例证据充分性审计

审计日期：2026-07-23  
任务编号：`G7-03-R01-FORMAL-CASE-EVIDENCE-AUDIT`

## 审计对象与标准

审计对象为 `r01_formal_case_selection_register.csv` 登记的四个优先案例。案例进入第五章正式机制分析至少需要同时满足：

1. 小问题干、参考解答和页码/整理文本可定位；
2. 最终编码四维度记录完整；
3. 对于正文要使用的维度与等级，A/B原始证据或裁决理由能说明具体题设触发语、解答步骤或条件，而不是仅以通用模板句代替；
4. 案例解释与题目实际要求不冲突。

第1、2项是结构性条件；第3、4项是进入论文机制结论的实质性条件。原始评分与裁决回填均保留不改，且本审计不反向篡改其值。

## 结构性发现

`r01_case_evidence_structural_audit_v1.csv` 显示：两份876行评分回填的证据文本高度重复。RATER-A仅有42种去重证据文本，RATER-B仅有76种；最常见的证据均是“题干要求……”等通用句式。最终表中还存在大量“A/B一致判定为L1/L2/L3/L4”记录。这些字段满足非空和结构门禁，但不能替代逐题可定位证据。

因此，结构性接收检查、信度计算、唯一分析表和描述统计的可复算性仍然成立；但它们不能单独证明四个候选案例已有足够证据进入机制解释正文。

## 处理决定

1. 四个案例继续保留为“结构性候选登记”，不删除原始编码、裁决、统计或选择记录；
2. 四案全部停止进入第五章正式机制结论，其中 `CASE-R01-01` 与 `CASE-R01-04` 不得沿用原登记的高阶解释；
3. 在获得逐题、可定位的补充证据并完成对应裁决更正或重新裁决之前，不得使用这四案写出模型建构L3、科学推理L3、科学论证L3或质疑创新L4的案例结论；
4. 第五章仍只能保留案例分析协议和教学设计建议，不得写作学生困难、教师意见、课堂可行性、教学效果或因果结论。

## 最小纠偏材料

每一个拟入正文案例须提供同一版式的补充裁决条目：`item_id`、维度、题干触发语及页码、参考解答关键步骤及页码、A/B原始判断、裁决结论、相邻等级排除理由、裁决者代号和日期。若新裁决改变任何 `present` 或 `level`，必须重新生成 `final_coding.csv`、正式描述统计、第四章对照QA和案例候选登记；不得只改第五章文字。

## 结论边界

本审计发现的是已归档数据的“案例证据充分性不足”，并不判断任何人的真实身份、独立性或主观过程。项目只能记录评分者和裁决者的自声明，不能独立验证其过程。该风险使当前数据不适合承担高阶案例机制结论，也提示第四章正式结果应继续标注为“待逐条证据充分性复核”的可复算描述结果。
