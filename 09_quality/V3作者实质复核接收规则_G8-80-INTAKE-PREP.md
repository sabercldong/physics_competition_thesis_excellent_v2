# V3作者实质复核完成副本接收规则

任务编号：`G8-80-INTAKE-PREP`

版本日期：2026-07-30

## 一、适用范围

本规则适用于作者完成P0、P1、P2三批、经合并工具恢复并通过全量 `filled` 校验的884行V3作者实质复核副本。当前项目尚未收到该完成副本，本文件只建立未来接收入口。

分批文件不得分别进入唯一编码表。三批必须先按G8-79规范顺序合并，合并文件才是G8-80的接收对象。

## 二、接收前条件

1. P0、P1、P2分别通过对应 `--item-priority` 成品校验。
2. 合并工具输出884行文件，并通过全量 `filled` 校验。
3. 实际复核代号、复核日期、逐行决定、复核标签、理由、证据位置和声明均已填写。
4. 来件文件名不含“空白”“模板”“测试”或“示例”等误导性状态。
5. 接收操作者使用匿名代码登记，不在公开包写入身份证号、电话、邮箱或账户信息。

## 三、接收命令

在项目根目录运行：

```bash
python3 07_analysis/scripts/intake_v3_author_review.py \
  "<884行完成副本路径>" \
  --intake-date "<实际接收日期YYYY-MM-DD>" \
  --received-by "<接收操作者代号>" \
  --output-dir "07_analysis/data/v3_author_review_intake/<接收批次目录>"
```

只有全量成品校验通过后，脚本才会创建接收目录。脚本将：

- 原样复制来件并将归档副本设为只读；
- 计算来件与归档副本SHA-256并要求完全一致；
- 生成单行接收登记；
- 生成程序性质量标记表；
- 生成接收报告；
- 始终保持“不放行”，等待G8-80人工QA。

## 四、自动拒收条件

出现以下任一情况时，脚本退出且不创建接收归档：

- 不是G8-79规范的884行全量文件；
- 表头或33个不可变字段被修改；
- 13个回填字段存在缺失或非法值；
- 保持、更正、待核实决定与复核标签、证据或状态逻辑冲突；
- 日期格式不正确；
- 归档复制后SHA-256与来件不一致；
- 输入路径与归档输出路径相同。

## 五、质量标记

结构通过后，脚本继续标记但不自动裁决：

| 类别 | 触发条件 | 严重度 |
|---|---|---|
| 通用理由 | 理由仅为“同意”“无问题”“符合标准”等 | 高 |
| 跨题重复理由 | 同一理由逐字复用于至少5个不同分析单元 | 高 |
| 跨题重复证据位置 | 同一证据位置逐字复用于至少9个不同分析单元 | 中 |
| 同题四维理由完全相同 | 同一分析单元四维理由逐字一致 | 中 |
| 未闭合记录 | 仍含待核实、待补证或待裁决 | 高 |
| 候选更正 | 作者提出更正候选 | 信息 |
| 复核元数据不唯一 | 存在多个复核代号或日期 | 信息 |

阈值用于形成复查队列，不代表命中记录一定错误。特别是同一题目四维可共享题干或解答位置，但仍需人工判断理由是否分别回应四个维度。

## 六、G8-80人工QA

接收器运行成功不等于G8-80完成。人工QA至少需要：

1. 核对来件来源、文件名、接收日期和复核声明是否与实际过程一致；
2. 逐项处理全部高风险标记和候选更正；
3. 对跨题重复理由与证据位置抽查原题和解答；
4. 检查P0全部记录，并从P1、P2各抽取不同届次和不同维度的记录复查；
5. 对所有待核实记录建立阻塞清单，不得强行转为确定标签；
6. 形成“接受、退回补正或部分阻塞”的逐项结论；
7. 只有QA明确接受的884行确定标签才能进入G8-68唯一表生成。

接收登记、程序校验和风险筛查只提供E3级程序证据，不证明复核人身份或学术判断正确。
